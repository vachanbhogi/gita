## 2023-10-27 - Safely Refactoring MainActor to Actor in Swift UI Contexts
**Learning:** When moving a `@MainActor` caching class to a Swift `actor` to offload work (e.g., image decoding) from the main thread, you must ensure you do not break synchronous API contracts. Swift's `NSCache` is natively thread-safe.
**Action:** When migrating `NSCache` wrappers from `@MainActor class` to `actor`, apply the `nonisolated` keyword to the cache access methods (`image(for:)`, `setImage(...)`) to preserve synchronous, flicker-free UI rendering while safely reaping the performance benefits of actor isolation for asynchronous fetching operations.

## 2024-05-18 - Synchronous Rendering for Cached Async Images in SwiftUI
**Learning:** Using `.task` to fetch images from an `actor` cache without checking the `nonisolated` synchronous method first causes unnecessary view re-renders and visual flickering. The asynchronous boundary of `.task` means the view renders a frame without the image (showing a placeholder) before the cached image is returned. Additionally, if the `id` parameter is omitted from `.task`, it will not trigger a refetch if the component is reused for a new URL but retains its identity.
**Action:** When creating SwiftUI components that display cached images (like favicons), introduce a computed property that synchronously resolves the image from the cache via a `nonisolated` method first, falling back to the `@State` image only if missing. Use `.task(id: url)` to properly handle URL changes on recycled views, and early-exit within the task if the synchronous cache check passes to save async overhead.
